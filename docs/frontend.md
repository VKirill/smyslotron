# Фронтенд (web/)

Три статических HTML-страницы, vanilla JS, без сборки и зависимостей. Деплой = сохранить
файл (angie отдаёт их напрямую, все data-фетчи с `cache: "no-cache"`).

## index.html — кабинет

Авторизация (вход/регистрация), карточки проектов (статус, прогресс-бар из
`status.json`, история пополнений, раскладка себестоимости), drag&drop загрузка.

- **Модалка-маппер**: превью таблицы, выбор разделителя, назначение колонок по
  вордстат-нотации (Запрос / Wordstat / "!Wordstat" / "[!Wordstat]" / Топоним / Вопрос),
  выбор вариантов эмбеддингов (один или A/B-набор). Окно показывается **всегда** —
  шаблон формата только подставляет колонки (зелёная пометка «формат узнан»).
- **Мультизагрузка в пополнение** («➕ Фразы»): несколько файлов очередью, каждый —
  своё окно подтверждения; append'ы идут с `defer_run: true`, один `/run` в конце;
  отмена прерывает очередь; итоговая сводка одним alert.

## view.html — просмотрщик

Главная страница анализа. `?p=<pid>` — id проекта; данные с
`api/projects/<pid>/data/`.

### Клиентская кластеризация

`loadTree()` парсит `.bin` (12 байт/слияние) → `cutLabels(tree, k)` применяет первые
`k` слияний union-find'ом → метки кластеров. `k = slider/10000 * (N-1)`.
`clusterize()` группирует индексы, режет кластеры с разными гео-ключами
(целевое гео вычитается) и применяет фильтр частотности. Всё — миллисекунды,
без сервера.

### Режимы отображения (взаимоисключающие, по приоритету)

1. **Сравнение шаблонов** (галочки в списке шаблонов): колонка = сохранённый шаблон
   со своими вариантом/режимом/срезом/мин.размером; консенсус-подсветка работает;
   поиск из шаблона игнорируется, общий поиск действует на все колонки.
2. **Режим анализа** (чекбокс «столбцы-поиски»): N колонок одной кластеризации,
   у каждой своё поле поиска в шапке; общий поиск отключён; фокус при вводе
   сохраняется (debounce 350мс + восстановление).
3. **Обычный режим**: колонки = включённые варианты эмбеддингов; при >1 —
   консенсус (зелёная папка = состав совпал во всех колонках, красная = отличается,
   в тултипе — с кем) и кнопка ⇄ (найти фразы кластера в соседних колонках).

Колонок >4 — раскладка в два ряда.

### Элементы

- Ползунок силы (шкала 0–10000, колёсико 0.02%/Shift 1%), режимы Hard/Средний/Soft,
  блок статистики сразу под ползунком;
- Счёт папок «один к одному»: мелкие группы из «Без группы» считаются папками
  (тултип с раскладкой «X групп + Y в Без группы»);
- Поиск ищет по фразам И по склеенным дублям, совпадения наверх, «Без группы»
  при поиске показывает только найденное;
- Фильтр частотности (порог + метрика основная/базовая) — внутри `clusterize`,
  поэтому согласован со всеми счётчиками и экспортом;
- Интент-чипы фраз и папок (И/К/Т/Н, ⚠ = смешанный), бейджи гео 📍 и вопросов ❓,
  «+N дубл.» с тултипом;
- Кнопки Я/G у фразы (по ховеру) — открыть выдачу Яндекса/Google;
- ⧉ — копировать уникальные фразы кластера; ⬇ «Текущий срез в CSV» — клиентский
  экспорт ровно того, что на экране (`exportSlice`);
- Целевое гео с datalist топ-30 гео, POST на сервер с debounce;
- Шаблоны фильтров: сохранение текущих настроек, применение кликом,
  сравнение галочками.

### Персистентность

`dbSet`/`dbGet` → `GET/POST /prefs/{key}` (debounce 400мс); localStorage — офлайн-
фолбэк и источник одноразовой миграции. Ключ `sem_prefs:<pid>`: вид, режим, ползунки
на каждый вид, поиск, целевое гео, режим анализа и его столбцы, отмеченные шаблоны.
Ключ `sem_tpl`: список шаблонов.

## merge.html — объединение CSV

Полностью клиентская страница (файлы не покидают браузер): парсит несколько
CSV/TXT (utf-8/windows-1251, кавычки, 4 разделителя), распознаёт колонки по тем же
алиасам, схлопывает точные дубли (max частот, OR флагов) и выгружает канонический
`merged.keys.csv` (UTF-8 BOM, `;`), готовый к загрузке в проект.
