# Пайплайн (pipeline.py)

Самодостаточный uv-скрипт (inline-зависимости: httpx, numpy, scipy, pymorphy3).
Запускается subprocess'ом: `uv run pipeline.py <project_dir> [--variants a,b,c] [--label-only] [--target-geo "..."]`.
Прогресс пишет в `<project_dir>/status.json`, результаты — в `<project_dir>/data/`.

## Стадии полного прогона

### 1. Загрузка ядра
`load_keys()` читает `keys.csv`. Основная частотность `primary`: «Очень точная»
(`[!Wordstat]`), если колонка заполнена; иначе «Точная»; иначе базовая. Она управляет
сортировками, выбором представителя дубля и оценкой трафика.

### 2. Морфологический анализ
`analyze()` через pymorphy3: мешок лемм каждой фразы, чанки предлогов (`_PREPS` —
последовательности «предлог + слово», фиксирующие смысловые связи), гео-ключи
(тег `Geox` — города/регионы), признак вопроса (`_QWORDS` + флаг keys.so).

### 3. Дедуп смысловых дублей
`pick_reps()`: кандидаты — фразы с одинаковым мешком лемм. Внутри группы фразы
сортируются по убыванию `primary`; жадный выбор лидеров: фраза `m` склеивается
с представителем `rep`, если косинус эмбеддингов `>= 0.97` (SURE) **или** чанки
предлогов совпали и косинус `>= 0.85` (FLOOR). Иначе `m` становится новым лидером.

- Контрольная пара: «молитва матери о дочери» / «молитва дочери о матери» — одинаковые
  леммы, разные чанки, косинус ~0.93 → НЕ склеиваются. Прогонять при правках дедупа.
- Частотности всех членов группы **суммируются** в представителя (`r_fp`, `r_fb`).
- Тексты поглощённых дублей сохраняются и показываются в интерфейсе («+N дубл.»).

### 4. Эмбеддинги (`EmbStore`)
**Глобальная база** `embeddings.db` (`pipeline_lib/store.py`, SQLite: `(variant, sha1(текст)) → float32`) —
общая для всех проектов: фраза оплачивается один раз навсегда, `_embed` сначала берёт из базы
и платит только за промахи. Поверх — локальный файловый кэш.
Файловый кэш `emb_<variant>.npy`, выровненный по порядку представителей.
**Инкрементальность**: если в кэше меньше строк, чем фраз — доэмбеддивается только
хвост и делается `np.vstack`. Поэтому порядок строк в `keys.csv` менять нельзя,
новые фразы — только в конец.

| Вариант | Источник | Особенности вызова |
|---|---|---|
| `openai`, `lemma`, `intent` | OpenAI `text-embedding-3-large` | батчи, конкурентность 32 (лимиты 10M TPM / 10K RPM) |
| `gemini`, `gem_sim`, `gem_query` | `gemini-embedding-2`, разные `taskType` | каждая фраза батча = 1 запрос → `RateLimiter` (скользящее минутное окно, `GEMINI_RPM`, дефолт 15000) + Retry-After |
| `voyage` | `voyage-3-large`, 2048d | OpenAI-совместимый API, батч 400 |
| `qwen` | DashScope `text-embedding-v4`, 2048d | compatible-mode, батч максимум 10 |
| `ensemble` | конкатенация нормированных openai+gemini | бесплатно |
| `openai1536`, `gemini768` | матрёшечные обрезки (MRL) | бесплатно |

Реестр вариантов: `TITLES` (названия), `DERIVED` (производные), `GEMINI_TASK`,
`COMPAT_API` (OpenAI-совместимые провайдеры). Новый вариант = ключ ≤20 символов
`[a-z0-9_]` (regex-whitelist выдачи в app.py).

### 5. HAC-деревья (`build_all`)
Косинусная матрица сходства → `scipy.cluster.hierarchy.linkage` тремя методами:
`complete` (hard), `single` (soft), `average` (avg). Каждое дерево сериализуется
в `data/<variant>_<method>.bin` (12 байт на слияние: `<iif` = int32 a, int32 b,
float32 distance). Автокалибровка порогов для серверного CSV — перцентили матрицы
(P_FINE=15, P_COARSE=75).

**Устойчивость**: каждый вариант в try/except — падение одного помечает его skipped
и не валит прогон; готовые `.bin` пропускаются (skip-if-exists); app.py автоматически
дожимает skipped-варианты повторным запуском (`retries < 3`).

### 5a. Автоаренда GPU на Vast.ai (`pipeline_lib/remote.py` + `gpu_hac.py`)
`build_trees()` в `run.py` сравнивает `n²·4·2.2` с `MemAvailable`; если локально не влезает —
`build_remote()`: ступень VRAM `pick_vram_step` (float32 `n²·4·2.3`, иначе float16 → 24/48/80/94/140 ГБ),
поиск самого дешёвого verified-оффера (`gpu_ram ≥`, `num_gpus=1`, `reliability ≥ 0.95`,
`direct_port_count ≥ 10`, `cuda ≥ 12`, цена ≤ `VASTAI_GPU_MAX_DPH`), создание через встроенный
PyTorch-шаблон (`template_hash f88cf873…`: sshd+torch+numpy), SSH-ключ аккаунта `~/.ssh/id_ed25519`
(проверяется/добавляется через `/api/v0/ssh/` ДО создания), endpoint как в vast CLI:
`public_ipaddr + ports["22/tcp"][0].HostPort`, фолбэк `ssh_host:ssh_port`. `scp -P`, `ssh -p`.
На карте выполняется `gpu_hac.py`: матрица дистанций блоками, затем **nearest-neighbor chain**
для complete/single/average (Lance–Williams по строке, O(n) на шаг) → полное дерево n−1 слияний,
отсортированное как у scipy. Домой: `{variant}_{hard,soft,avg}.bin` + `thr.json`; размер дерева
валидируется; `finally: destroy`; аренда → `costs.json` (`vast_usd`).
Проверка на полном ядре 104 602 смысла vs scipy: avg/soft — разбиения идентичны на всех порогах,
hard — 99.3–99.9 % папок (float-ничьи в complete-linkage). CPU-путь удалён намеренно.

### 6. Гео-разрез
`split_by_geo()`: кластер, внутри которого больше одного гео-ключа, режется по гео.
Целевой регион (`--target-geo "москва, мск, мо"`) — его слова вычитаются из гео-ключей,
пустой остаток = «наш регион» = сливается с безгеошными фразами.

### 7. Экспорт
`data/queries.json` (фразы, частоты, дубли, гео, вопросы), `data/meta.json`
(варианты и методы), `result.csv` (UTF-8 BOM, `;`, русские заголовки),
`report.md`, `costs.json` (накопительный).

## Режим --label-only (интенты)

`deepseek_label_phrases()`: пофразовая разметка через DeepSeek chat/completions.

- Словарь `phrase_intents.json` `{фраза: интент}` живёт независимо от кластеров;
  размечаются только отсутствующие фразы (инкрементально).
- Вопросные фразы получают «информационный» без запроса к API.
- 4 класса: информационный / коммерческое исследование / транзакционный / навигационный.
- Батчи по 40 фраз с id-матчингом, `response_format: json_object`, temperature 0.1,
  до 1500 параллельных соединений (`httpx.Limits(max_connections=1600)`).
- Настройки через env: `DEEPSEEK_MODEL` (дефолт deepseek-v4-flash), `DEEPSEEK_REASONING`
  (0/1 — thinking-режим), `DEEPSEEK_EFFORT` (high/max), `DEEPSEEK_TEMP` — см. `ds_params()`.
- Результат выравнивается на текущий список представителей → `data/intents.json`;
  `result.csv` получает колонки «Интент фразы / Интент кластера / Вторичный / Риск смешения».
